1. About and contact

SQL Cockpit is a database-analysis application that turns questions into proposed SQL, shows query results, and lets you keep useful analyses. This policy describes the application operated at sql-data-cockpit.vercel.app.

For privacy questions or requests, contact the operator at omb4027@gmail.com.

2. Information we process

The information processed depends on the features you use and what is available in the deployed version.

  • Account information: your email address, username, password hash, email-verification status, session information and account timestamps. Passwords are stored as hashes rather than as recoverable account passwords.
  • Connection and model settings: database host, port, database name, username, password, connection status and any model-provider API key you configure. Connection credentials, optional reference documents and model keys use field-level encryption in their saved application records.
  • Analysis content: questions, uploaded reference documents, schema information, generated SQL, query-result values, model answers, conversation history, saved analyses and result snapshots. Workflow checkpoints can also retain context needed to continue an interrupted analysis.
  • Operational information: connection-test timestamps, usage counters, and IP addresses used for request throttling. Hosting services may also process IP addresses, request metadata and operational logs.

Information you include in a question or reference document becomes part of that analysis content, even when you include it accidentally.

3. Why we use it

We process this information to create and secure accounts, verify email ownership, recover access, connect authorized databases, generate and execute approved queries, provide answers, save and rerun analyses, and investigate service errors or abuse.

The application does not implement advertising or the sale of personal information. The operator and service providers may access information as necessary to operate, support and secure the service.

4. AI and connected databases

SQL Cockpit currently uses Groq for model requests. Depending on the task, requests can include your question, relevant conversation context, schema details, uploaded business references, proposed SQL, database errors and query-result values. Database values used as model context can contain personal or confidential information.

This service is not a zero-data-egress database tool. Information used in an analysis can leave your database and be processed by the backend, model provider and application storage.

After approval, SQL is executed by the backend against the selected database. Only connect sources you are authorized to use, and grant the database role access only to the tables and columns this workspace should be allowed to query. Review proposed SQL and avoid submitting unnecessary sensitive information.

The model provider’s own data-handling terms also apply. This policy does not promise that provider processing has no retention or that all providers use the same controls.

5. Google and account email

The operator authorizes the Gmail API with the gmail.send scope to send service messages, such as email-verification and password-reset links, from the operator’s mailbox. This integration does not request permission to read the mailbox. It is separate from creating a SQL Cockpit account; users are not asked to authorize their own Gmail inboxes.

Google processes the recipient address, email headers and message body when delivering these emails. Verification and reset messages contain a time-limited account link. Operator OAuth credentials and refresh authorization are kept in backend secret settings; short-lived access tokens are used to call Google’s mail service.

We use the Google authorization and related data only to provide these service-email functions. We do not use it for advertising or model training. SQL Cockpit’s use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including its Limited Use requirements.

7. Cookies and browser requests

SQL Cockpit uses an HTTP-only refresh-session cookie to maintain sign-in. Access tokens are held in browser memory rather than intentionally saved to local storage. The browser also holds temporary interface and query state while the app is open.

The main application loads fonts from Google Fonts and a chart library from Plotly’s CDN. Those requests expose normal connection information, such as an IP address and browser request headers, to the resource providers. Provider-managed hosting logs or controls may also apply.

8. Retention and deletion

Account records, conversation content, saved analyses, connection settings and workflow context can remain stored while the service is in use. A general automatic retention or purge schedule is not currently implemented. Token expiry limits whether an authentication link or session can be used; it does not necessarily erase the stored record.

Available controls let you remove connections, reference documents or conversations. Saved analyses and their result snapshots currently require an operator request for removal. Removing a connection or document does not automatically erase information already copied into a conversation, saved result or workflow checkpoint. Deleting a conversation from the normal application records does not guarantee immediate removal of its checkpoint copies, backups or provider records.

To request account deletion, access to your information, or removal of retained analysis context, email omb4027@gmail.com. These requests require operator review and ownership verification; the application does not currently offer automated account deletion or a guaranteed deletion deadline. Some information may need to be retained for security or applicable obligations.

Field-level encryption for saved credentials and references is not a claim that all conversation, result and checkpoint content uses the same application-level encryption. Access controls and provider protections also apply, and no system can guarantee absolute security.

9. Your choices and requests

You can choose which database role to connect, omit optional reference documents, inspect a proposed query before approving it, and use the available removal controls. Do not share a personal workspace login or connect confidential databases through a shared demo account.

You can contact the operator about privacy, access, correction or deletion requests. Available rights and requirements can depend on your location and circumstances. Do not send database passwords, API keys or full database exports with a support request.
